FairPlay product design, v2 draft
Teacher dashboard and student app. Ten clickable prototypes below the overview: every button changes the screen and says what it did.
Read this first: what this is and is not
A design draft for discussion, not shipped code. I reviewed DKU OJ in text mode only (no screenshots), so the IDE layout follows my notes: problem list left, tabs Description / AI Hints / Result / Editorial / Submissions, language picker, Input and Output panes, Run Code, Submit with a live score. It matches the structure, not the pixels. The speed numbers are design targets we must measure, not results. Question-type counts come from the DKU OJ review and the standalone question library; the library is not merged into the main app yet.

Why a teacher moves to us

Not because the editor is nicer. Because one place gives them the lock, the IDE, the live room and an explainable integrity report. DKU OJ today leans on Safe Exam Browser with hand-pasted key hashes and shows the teacher nothing live.

Teacher rule: DKU OJ's menu, by exam kind

The menu follows DKU OJ (Courses, Questions, Exams, Grading) so a DKU teacher is not lost. One Exams list holds quizzes, midterms, finals and homework; the Kind you pick fills in every default. Adding a question opens a picker of question types, filtered to what the subject uses.

Student rule: three screens

Enter code, take exam, done. One Run button, one Submit button, no menus, no settings. Everything the lock needs (quit apps, permissions) is one checklist before the exam, not a surprise during it.

How features reach each subject

The product is built once, but a teacher only meets what their subject uses. Features come in packs: Core (12 types, always on), Code and IDE (6), Math and science (4), Visual (4), Language and media (4), Data and sheets (2). The superadmin switches packs per subject (A1). The class's subject then decides three things: what the type picker shows (Biology sees 16 of 32 types and no code editor), what the question bank offers, and what is bundled onto student Macs (no editor or Python runtime for a Biology exam). Teachers can ask for a hidden pack with one click and the admin answers in one click. The menu, live room, grading, analytics and integrity report are the same for everyone.

Honest check: is this clearly better than DKU OJ?
Not on the surface. The first version of this design was not, and the menu is now deliberately close to DKU OJ's. The real advantages are the lock, the live room and the integrity report, which DKU OJ does not have. The picker and the one-line setup are meant to be faster, but "a quiz in five minutes" is a target I have not measured. Next step: put two or three DKU professors in front of both, side by side, and time them.

Teacher screens

T1
Menu: Home, Courses, Questions, Exams, Grading, Reports
Exams by kind (quiz, midterm, final, homework) as list, by course or calendar; kind chooser for a new exam; Course to Class; Canvas CSV roster import in three steps.
T2
Exam editor: setup in one line, questions from the type picker
+ Add question opens a picker of tiles by group, showing only the types enabled for the class's subject. Also paste several, AI draft, from bank; code tests; student preview; open or publish.
T3
Question types: all 32, what teacher fills, what student sees
Pick a subject first (CS, Math, Chem, Biology, Languages, Economics) and see only the types that professor gets, with a sample question, what the student sees and how it is graded. Other types show as "not enabled for this subject".
T4
Live room
Seat grid, personal deadlines, flags, student drawer, release device, offline exit, problem reports.
T5
Grading workbench and gradebook
Queue, answer versions, AI feedback with teacher override, Release All, Finalize, Canvas export.
T6
Integrity report
Anomaly percentile, class timeline, every flag linked to raw events. A human decides.
T7
Results and analytics
Score spread, section against section, every question's difficulty, each student's topics and trend, topic map. Charts you can click into.
T8
Classroom-style dashboard and Library
Course cards, class page with Stream, Classwork, People, Grades; To review; Calendar; and a Library of questions, templates, materials and rubrics shared as Mine, My department, University. Switch between CS, Math and Biology to see each subject's own Library tab.
A1
Superadmin: feature packs per subject
Switch Code and IDE, Math, Visual, Language packs on or off per subject. Teachers can ask for more.

Student screens

S1
Sign-in, home, join class, start code, pre-lock checklist, done, results
Setup link or NetID sign-in, exam list, the checklist that replaces surprises, result and feedback view.
S2
Exam workspace, rebuilt for comfort
One question at a time, quiet top bar, dots to move around, review screen before hand-in. Five exams, each for one course: CS, Math, Chemistry, Biology, Languages. The code editor appears only in the CS exam.
S3
Student dashboard (Classroom-style)
Next exam card with get-ready checklist, one card per course, course page with Stream, Classwork, My grades, People; To-do, Calendar, My grades, and Practice only for courses with coding. Each exam belongs to one course.

How to read the prototypes

Press Play on a board (or open it full window). Click anything. A blue strip at the bottom of each board prints the outcome of your last click, so you can read the whole flow without guessing. Left column of each board is the page itself; the "Spec" card under it lists what every element does and the rules behind it.

IDE speed budget (design targets, to be measured)

I have not profiled DKU OJ's IDE. I assume each run is a round trip to a judge queue, which is the usual cause of "slow". Our design removes the round trip for the common case.
